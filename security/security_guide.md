# SQL Server 安全管理体系指南

## 概述

本指南旨在构建一套完整的数据库安全管理体系，涵盖用户与角色管理、行级安全性、透明数据加密（TDE）、审计追踪四大核心领域，确保数据库服务及应用的全面安全保护。

---

## 1. 用户与角色管理

### 1.1 用户账户创建规范

#### 1.1.1 命名规范
- **登录名命名规则**：`[部门缩写]_[姓名拼音]_[序号]`，例如：`DEV_WangWei_01`
- **数据库用户名命名规则**：与登录名保持一致
- **服务账户命名规则**：`SVC_[系统/应用名]_[环境]`，例如：`SVC_ART_CONTEST_PROD`

#### 1.1.2 创建流程
1. 提交账户申请单
2. 安全管理员审核
3. 创建登录名和用户
4. 分配最小必要权限
5. 用户签收确认

### 1.2 密码策略

#### 1.2.1 密码复杂度要求
- 最小长度：12位
- 必须包含：大写字母、小写字母、数字、特殊字符
- 禁止使用：用户名、公司名称、连续重复字符

#### 1.2.2 密码生命周期
- 密码有效期：90天
- 密码历史：保留最近5个密码
- 账户锁定：连续5次失败登录后锁定30分钟

### 1.3 角色定义与权限分配

#### 1.3.1 预定义角色

| 角色名称 | 权限级别 | 适用场景 |
|---------|---------|---------|
| `db_owner` | 完全控制 | DBA、系统管理员 |
| `db_datareader` | 只读 | 报表用户、数据分析 |
| `db_datawriter` | 读写 | 应用服务账户 |
| `db_ddladmin` | 架构修改 | 开发人员 |
| `db_securityadmin` | 权限管理 | 安全管理员 |

#### 1.3.2 自定义角色

| 角色名称 | 权限范围 | 说明 |
|---------|---------|------|
| `APP_ReadOnly` | 只读访问特定业务表 | 第三方查询服务 |
| `APP_WriteOnly` | 仅插入权限 | 数据采集服务 |
| `APP_Report` | 报表生成权限 | 报表服务账户 |

#### 1.3.3 权限分配原则
- **最小权限原则**：只授予完成工作所需的最小权限
- **职责分离**：开发、测试、运维权限分离
- **定期审计**：每季度进行权限审计

### 1.4 用户生命周期管理

#### 1.4.1 账户状态

| 状态 | 说明 | 处理方式 |
|-----|------|---------|
| Active | 正常使用 | 定期检查 |
| Inactive | 30天未登录 | 发送提醒通知 |
| Suspended | 临时禁用 | 保留数据，禁止登录 |
| Disabled | 永久禁用 | 离职人员账户 |
| Expired | 密码过期 | 强制修改密码 |

#### 1.4.2 流程

```
创建 → 启用 → 使用 → 定期审查 → (禁用/删除)
```

## 2. 行级安全性

### 2.1 概念与原理

行级安全性（Row-Level Security, RLS）允许数据库管理员根据用户身份或角色限制对表中特定行的访问。

### 2.2 访问控制策略

#### 2.2.1 基于角色的访问控制

```
场景：不同部门只能访问本部门数据

- 部门A用户 → 只能查看部门A的数据行
- 部门B用户 → 只能查看部门B的数据行
- 管理员 → 可以查看所有数据
```

#### 2.2.2 基于用户属性的访问控制

```
场景：用户只能访问自己创建的数据

- 用户A → 只能查看自己创建的记录
- 用户B → 只能查看自己创建的记录
- 管理员 → 可以查看所有记录
```

#### 2.2.3 基于时间的访问控制

```
场景：敏感数据在特定时间后才能访问

- 财务数据 → 每月10日后可访问上月数据
- 审计数据 → 审计完成后可访问
```

### 2.3 实现方法

#### 2.3.1 创建安全函数

安全函数定义行级访问规则，返回布尔值决定用户是否可以访问特定行。

#### 2.3.2 创建安全策略

安全策略将安全函数应用到目标表，实现行级过滤。

### 2.4 适用场景

| 场景 | 描述 | 示例 |
|-----|------|------|
| 多租户隔离 | 不同租户数据隔离 | SaaS应用 |
| 部门隔离 | 不同部门数据隔离 | 企业ERP |
| 数据脱敏 | 敏感数据按角色显示 | 医疗记录 |
| 合规要求 | 满足监管合规 | 金融数据 |

## 3. 透明数据加密（TDE）

### 3.1 加密层次结构

```
层级1: 数据库加密密钥 (DEK)
    ↓
层级2: 服务器证书/非对称密钥
    ↓
层级3: 主密钥 (SMK)
    ↓
层级4: Windows DPAPI
```

### 3.2 密钥管理策略

#### 3.2.1 密钥存储
- 主密钥存储在数据库主文件中
- 证书存储在master数据库
- 定期备份密钥到安全位置

#### 3.2.2 密钥轮换
- 数据库加密密钥：每年轮换
- 服务器证书：每2年轮换
- 主密钥：每3年轮换

### 3.3 加密算法选择

| 算法 | 用途 | 密钥长度 | 推荐场景 |
|-----|------|---------|---------|
| AES-256 | 数据加密 | 256位 | 生产环境 |
| AES-128 | 数据加密 | 128位 | 测试环境 |
| RSA-2048 | 密钥保护 | 2048位 | 证书加密 |

### 3.4 性能影响评估

| 操作类型 | 影响程度 | 说明 |
|---------|---------|------|
| 查询 | 低 (2-5%) | 加密/解密在IO层 |
| 写入 | 低 (3-7%) | 写入时加密 |
| 备份/恢复 | 中 (10-15%) | 备份文件也加密 |
| TempDB | 无 | 临时数据不加密 |

### 3.5 实施步骤

1. 创建数据库主密钥
2. 创建服务器证书
3. 创建数据库加密密钥
4. 启用TDE加密
5. 备份证书和私钥
6. 验证加密状态

### 3.6 列级加密

对于敏感列（如身份证号、银行卡号），可以采用列级加密：

| 数据类型 | 加密方式 | 示例 |
|---------|---------|------|
| 身份证号 | AES-256 | 存储加密值 |
| 银行卡号 | 格式保留加密 | 显示部分掩码 |
| 密码 | 哈希加密 | SHA2_512 |

## 4. 审计追踪

### 4.1 审计策略

#### 4.1.1 需要审计的事件类型

| 事件类别 | 具体事件 | 审计级别 |
|---------|---------|---------|
| 登录事件 | 成功登录、失败登录、注销 | 高 |
| 对象访问 | 表访问、视图访问、存储过程执行 | 中 |
| 数据操作 | INSERT、UPDATE、DELETE | 高 |
| 权限变更 | 用户创建、权限授予/撤销、角色变更 | 高 |
| 架构变更 | CREATE、ALTER、DROP | 高 |
| 安全事件 | 权限拒绝、敏感数据访问 | 高 |

#### 4.1.2 审计范围

```
- 所有数据库用户操作
- 所有DDL操作
- 所有权限变更
- 敏感数据访问
- 失败的登录尝试
```

### 4.2 日志存储要求

#### 4.2.1 存储位置
- **主日志**：SQL Server审计文件
- **归档日志**：异地存储（如Azure Blob、AWS S3）
- **安全日志**：独立安全信息和事件管理(SIEM)系统

#### 4.2.2 存储格式
- 文件格式：XEL（扩展事件日志）
- 编码：UTF-8
- 压缩：GZIP压缩存储

### 4.3 保留期限

| 日志类型 | 保留期限 | 说明 |
|---------|---------|------|
| 在线日志 | 90天 | 快速查询 |
| 归档日志 | 7年 | 合规要求 |
| 审计报告 | 永久 | 法律证据 |

### 4.4 审计分析

#### 4.4.1 定期审计任务

| 频率 | 任务 | 负责人 |
|-----|------|--------|
| 每日 | 登录失败分析 | 安全管理员 |
| 每周 | 权限变更审计 | DBA |
| 每月 | 数据访问审计 | 审计员 |
| 每季度 | 全面安全评估 | 安全团队 |

#### 4.4.2 告警规则

| 告警类型 | 触发条件 | 响应级别 |
|---------|---------|---------|
| 暴力破解 | 5分钟内10次失败登录 | 紧急 |
| 权限异常 | 非工作时间权限变更 | 高 |
| 数据泄露 | 大量数据导出 | 紧急 |
| 系统异常 | 数据库异常关闭 | 高 |

### 4.5 审计实施

#### 4.5.1 使用SQL Server审计功能
- 创建审计对象
- 创建服务器审计规范
- 创建数据库审计规范
- 配置审计目标

#### 4.5.2 使用扩展事件
- 创建扩展事件会话
- 捕获关键事件
- 配置事件输出目标
